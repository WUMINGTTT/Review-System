## 1. 系统概述

本系统是一个面向组织内部的 **活动评价管理系统**，核心场景为：

> 组织者创建一次活动评价 → 录入被评价人 → 逐人填写评分与评语 → 全部完成后提交 → 审核者审核 → 通过则归档 / 打回则重新评价

系统围绕 **草稿机制** 和 **状态流转** 两个核心概念构建，确保评价工作可中断、可恢复、可追溯。

## 2. 用户角色定义

| 角色 | 职责 | 关键能力 |
|------|------|---------|
| **组织者 (Organizer)** | 发起评价、录入被评价人、填写评分、提交评价 | 创建草稿、编辑评价、提交、查看打回原因 |
| **审核者 (Reviewer)** | 审核已提交的评价结果 | 查看评价明细、通过/打回 |
| **管理员 (Admin)** | 系统管理、用户管理 | 用户增删改查、角色分配、基础数据维护 |

> 注：一个用户可同时拥有多个角色（如某人既是 A 活动的组织者，也是 B 活动的审核者）。

## 3. 核心业务流程

### 3.1 评价生命周期（状态机）

```
                        ┌─────────────┐
                        │  草稿 DRAFT  │ ← 组织者创建 / 中途保存
                        └──────┬──────┘
                               │ 组织者点击"提交"
                               ▼
                     ┌──────────────────┐
                     │ 已提交 SUBMITTED  │ ← 进入公共区域，审核者可见
                     └────────┬─────────┘
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
          ┌─────────────┐     ┌──────────────┐
          │ 通过 APPROVED│     │ 打回 REJECTED │
          └──────┬──────┘     └──────┬───────┘
                 │                   │ 组织者修改后重新提交
                 ▼                   │ (回到 SUBMITTED)
          ┌─────────────┐            │
          │ 归档 ARCHIVED│◄───────────┘ (可选：打回后直接回到草稿)
          └─────────────┘
```

### 3.2 各阶段详细说明

| 状态 | 触发条件 | 可执行操作 | 说明 |
|------|---------|-----------|------|
| **DRAFT** | 组织者创建新评价 | 编辑活动信息、管理被评价人、填写/修改评分、保存、删除 | 系统自动保存（每 30s 或字段变更时），防止丢失 |
| **SUBMITTED** | 组织者主动提交 | 审核者查看、审核 | 提交时校验：所有被评价人必须已完成评分 |
| **REJECTED** | 审核者打回 | 组织者查看打回原因、修改评分、重新提交 | 打回时审核者必须填写理由 |
| **APPROVED** | 审核者通过 | 查看详情、归档 | 审核者可附加审核意见 |
| **ARCHIVED** | 审核者确认归档 | 仅查看 | 归档后不可再修改，作为历史记录永久保存 |

### 4.2 核心数据交互流程

#### 流程一：创建与编辑评价（草稿）

```
组织者 ─→ [前端表单] ─→ POST /api/evaluations ─→ 创建草稿 (status: DRAFT)
                                                  │
组织者 ─→ [评分页]   ─→ PUT /api/evaluations/:id ─→ 更新活动信息 & 评分明细
         [自动保存]   ─→ PATCH /api/evaluations/:id/auto-save ─→ 增量保存
```

#### 流程二：提交评价

```
组织者 ─→ [点击提交] ─→ POST /api/evaluations/:id/submit
                           │
                           ├─→ 后端校验：所有被评价人是否均已评分
                           ├─→ 校验通过：status → SUBMITTED，记录提交时间
                           ├─→ 校验失败：返回未完成项列表
                           └─→ 推送通知给审核者
```

#### 流程三：审核评价

```
审核者 ─→ [审核页] ─→ POST /api/evaluations/:id/approve  ─→ status → APPROVED
       ─→ [审核页] ─→ POST /api/evaluations/:id/reject   ─→ status → REJECTED
                                                            └─→ 推送通知给组织者
```

#### 流程四：归档

```
审核者 ─→ [确认归档] ─→ POST /api/evaluations/:id/archive ─→ status → ARCHIVED
                                                              └─→ 从活跃列表移入归档库
```

### 4.3 自动保存策略

| 策略 | 实现方式 | 说明 |
|------|---------|------|
| 定时自动保存 | `setInterval` 30s | 定期将当前表单数据 PATCH 到后端 |
| 字段变更保存 | `watch` + 防抖 (debounce 2s) | 单个字段修改后延迟保存 |
| 离开页面保存 | `onBeforeRouteLeave` | 切换路由前提示并保存 |
| 浏览器崩溃恢复 | `localStorage` 临时缓存 | 本地保留最近一次编辑快照，重进页面时对比恢复 |

### 5.2 Prisma Schema 设计

> 采用 **Prisma** 作为 ORM，数据库使用 **MySQL**。Prisma Schema 是数据模型的唯一定义来源，
> 运行 `prisma generate` 后自动生成 TypeScript 类型，无需手写接口定义。

```prisma
// prisma/schema.prisma

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "mysql"
  url      = env("DATABASE_URL")
}

model User {
  id           Int       @id @default(autoincrement())
  username     String    @unique
  password     String
  realName     String    @map("real_name")
  department   String
  phone        String?
  avatar       String?
  roles        String    // JSON 字符串，如 '["organizer","reviewer"]'
  isActive     Boolean   @default(true) @map("is_active")
  createdAt    DateTime  @default(now()) @map("created_at")
  updatedAt    DateTime  @updatedAt @map("updated_at")

  // 关联
  organizedEvals   Evaluation[]  @relation("Organizer")
  reviewedEvals    Evaluation[]  @relation("Reviewer")
  ratingItems      RatingItem[]
  notifications    Notification[]

  @@map("users")
}

model Evaluation {
  id           Int             @id @default(autoincrement())
  title        String
  description  String?
  eventDate    DateTime        @map("event_date")
  organizerId  Int             @map("organizer_id")
  reviewerId   Int             @map("reviewer_id")
  status       EvaluationStatus @default(DRAFT)
  rejectReason String?         @map("reject_reason")
  reviewComment String?        @map("review_comment")
  submittedAt  DateTime?       @map("submitted_at")
  reviewedAt   DateTime?       @map("reviewed_at")
  archivedAt   DateTime?       @map("archived_at")
  createdAt    DateTime        @default(now()) @map("created_at")
  updatedAt    DateTime        @updatedAt @map("updated_at")

  // 关联
  organizer    User            @relation("Organizer", fields: [organizerId], references: [id])
  reviewer     User            @relation("Reviewer", fields: [reviewerId], references: [id])
  participants Participant[]
  ratingItems  RatingItem[]

  @@index([organizerId])
  @@index([reviewerId])
  @@index([status])
  @@map("evaluations")
}

enum EvaluationStatus {
  DRAFT
  SUBMITTED
  REJECTED
  APPROVED
  ARCHIVED
}

model Participant {
  id           Int        @id @default(autoincrement())
  evaluationId Int        @map("evaluation_id")
  name         String
  department   String
  position     String?
  phone        String?

  // 关联
  evaluation   Evaluation @relation(fields: [evaluationId], references: [id], onDelete: Cascade)
  ratingItems  RatingItem[]

  @@index([evaluationId])
  @@map("participants")
}

model ScoreDimension {
  id          Int     @id @default(autoincrement())
  name        String
  description String?
  maxScore    Int     @map("max_score") @default(100)
  weight      Float   @default(1.0)
  isActive    Boolean @default(true) @map("is_active")
  createdAt   DateTime @default(now()) @map("created_at")
  updatedAt   DateTime @updatedAt @map("updated_at")

  @@map("score_dimensions")
}

model RatingItem {
  id             Int              @id @default(autoincrement())
  evaluationId   Int              @map("evaluation_id")
  participantId  Int              @map("participant_id")
  evaluatorId    Int              @map("evaluator_id")
  comments       String?
  totalScore     Float            @default(0) @map("total_score")
  status         RatingItemStatus @default(PENDING)
  savedAt        DateTime?        @map("saved_at")
  submittedAt    DateTime?        @map("submitted_at")
  createdAt      DateTime         @default(now()) @map("created_at")
  updatedAt      DateTime         @updatedAt @map("updated_at")

  // 关联
  evaluation     Evaluation       @relation(fields: [evaluationId], references: [id])
  participant    Participant      @relation(fields: [participantId], references: [id])
  evaluator      User             @relation(fields: [evaluatorId], references: [id])
  dimensionScores DimensionScore[]

  @@unique([evaluationId, participantId, evaluatorId])
  @@index([evaluatorId, status])
  @@map("rating_items")
}

enum RatingItemStatus {
  PENDING
  DRAFT
  SUBMITTED
}

model DimensionScore {
  id             Int    @id @default(autoincrement())
  ratingItemId   Int    @map("rating_item_id")
  dimensionId    Int    @map("dimension_id")
  dimensionName  String @map("dimension_name")
  score          Float
  maxScore       Int    @map("max_score")
  weight         Float

  // 关联
  ratingItem     RatingItem @relation(fields: [ratingItemId], references: [id], onDelete: Cascade)

  @@index([ratingItemId])
  @@map("dimension_scores")
}

model Notification {
  id        Int              @id @default(autoincrement())
  userId    Int              @map("user_id")
  type      NotificationType
  title     String
  content   String
  relatedId Int?             @map("related_id")
  isRead    Boolean          @default(false) @map("is_read")
  createdAt DateTime         @default(now()) @map("created_at")

  // 关联
  user      User             @relation(fields: [userId], references: [id])

  @@index([userId, isRead])
  @@map("notifications")
}

enum NotificationType {
  EVALUATION_SUBMITTED
  EVALUATION_APPROVED
  EVALUATION_REJECTED
  EVALUATION_ARCHIVED
  ASSIGNED_AS_REVIEWER
  ASSIGNED_AS_PARTICIPANT
  DEADLINE_REMINDER
}
```

### 5.3 设计说明

| 决策 | 理由 |
|------|------|
| Participant 改为独立表 | 关系型数据库下，独立表支持外键约束和级联删除，比嵌入式更规范 |
| DimensionScore 改为独立表 | 评分明细独立存储，便于按维度统计分析 |
| roles 用 JSON 字符串存储 | MySQL 不支持数组字段，用 JSON 字符串 + 应用层序列化 |
| 状态用枚举 (enum) | Prisma 原生支持枚举，映射为 MySQL ENUM 类型，比字符串更严格 |
| 所有表名/字段名用 snake_case | MySQL 惯例，Prisma 通过 @map 映射为 camelCase |
| 索引设计 | 根据查询模式添加索引：按状态筛选、按用户查询、复合唯一索引防重复评分 |

## 7. 前端页面架构

### 7.1 页面结构（路由设计）

```
/                           → 重定向到 /dashboard
/login                      → 登录页

/layout (主布局)
├── /dashboard              → 工作台（首页看板）

│   ├── /evaluations/:id    → 评价详情/编辑

- 管理功能（维度管理、用户管理）收纳到"我的"页面内
- 页面内容全宽展示，最大化利用小屏幕空间

### 7.3 选择此布局的理由

| 考虑因素 | 方案 | 理由 |
|---------|------|------|
| 适配策略 | **移动端优先** | 后续开发小程序端，网站端需在手机浏览器中体验流畅 |
| PC 导航 | **可折叠侧边栏** | 屏幕够大时展示完整菜单，小屏自动收起 |
| 移动导航 | **底部 Tab 栏** | 符合移动端操作习惯，拇指可轻松触及，类似微信/支付宝 |
| 内容策略 | **卡片化替代表格** | 移动端表格横向溢出严重，卡片列表天然适配窄屏 |
| 触控优化 | **增大点击区域** | 按钮最小 44px、表单输入全宽、间距充足 |

## 10. 状态管理方案

使用 **Pinia** 管理前端状态，按功能域划分 Store：

```
stores/
├── auth.ts           # 认证状态（用户信息、Token、登录/登出）
├── evaluation.ts     # 评价活动状态（当前编辑中的评价数据）
├── rating.ts         # 评分状态（当前评分表单数据、自动保存状态）
├── dimension.ts      # 评分维度（维度列表缓存）
└── app.ts            # 全局状态（侧边栏折叠、消息通知等）

// stores/evaluation.ts 核心结构

## 11. 安全与权限策略

### 11.1 认证方案

```
注册: POST /api/auth/register { username, password, realName, email? }
      → 后端校验 → 加密密码 → 存入数据库 → 返回成功

主登录: POST /api/auth/login { username, password }
        → 后端验证用户名密码 → 签发 JWT → 返回 token + 用户信息

第二登录: POST /api/auth/login-by-email { email, password }
          → 后端验证邮箱密码 → 签发 JWT → 返回 token + 用户信息
          → 前提：用户已绑定邮箱

前端存储: JWT 存入 localStorage
后续请求: Authorization: Bearer <token>
```

### 11.2 权限控制（RBAC）

```typescript
// 后端中间件：roleGuard('organizer', 'admin')
const roleGuard = (...allowedRoles: string[]) => {
  return (req, res, next) => {
    if (!allowedRoles.includes(req.user.role)) {
      return res.status(403).json({ code: 403, message: '无权限访问' });
    }
    next();
  };
};
```

| 操作 | organizer | reviewer | admin |
|------|-----------|----------|-------|
| 创建评价 | ✅ | ❌ | ✅ |
| 编辑自己的草稿 | ✅ | ❌ | ✅ |
| 提交评价 | ✅ | ❌ | ❌ |
| 查看公共列表 | ✅ | ✅ | ✅ |
| 审核评价 | ❌ | ✅ | ✅ |
| 归档评价 | ❌ | ✅ | ✅ |
| 管理维度 | ❌ | ❌ | ✅ |
| 管理用户 | ❌ | ❌ | ✅ |
